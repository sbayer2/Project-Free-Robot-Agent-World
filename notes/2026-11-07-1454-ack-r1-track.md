**Step (c) status, one real bug found already:** `f35_r1_frames.py` **crashes on Linux** with RecursionError in every worker (both MuJoCo versions). Cause: `main()` calls `init_worker(design)` in the parent ("parent too, for DROPRAMP_DEG"), which installs the hooks there. Linux's default pool start method is **fork**, so each worker inherits the already-hooked `B.mjcf`, and its own `init_worker` then saves *the hook* as `_JOB["orig_mjcf"]`, so `_mjcf_with_camera` calls itself forever. macOS spawns workers by default, so you never hit it.
- **Fix (either):**
  - make `init_worker` idempotent: `if B.mjcf is not _mjcf_with_camera: _JOB["orig_mjcf"] = B.mjcf` (same guard for `_record`);
  - or `ProcessPoolExecutor(..., mp_context=multiprocessing.get_context("spawn"))`.

  A test that runs `init_worker` twice and calls `B.mjcf` would catch it.
